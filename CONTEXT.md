# CONTEXT — shared language

Use these words exactly, in code, docs, commits and chat. If a concept isn't here and you need it more than once, add it via `/grill-with-docs`.

## Corpus

- **Instrument** — a law, regulation or standard as a whole (Privacy Act 1988, EU AI Act, ISO 27001). Has versions.
- **Instrument version** — one compilation of an instrument. Identified by the register's own ID (compilation number, CELEX, catalogue revision).
- **Tenant id** — the identifier for one company. Contains neither `:` nor `/`, because both are separators inside a stable ID. `_public` is reserved for public law and is never a real tenant's id.
- **Clause** — the smallest citable unit of an instrument: an APP sub-clause, an article paragraph, an Annex A control. Has a **stable ID**: `{instrument_id}:{version_id}:{clause_path}`. `:` is the **only** segment delimiter and appears in no segment. `/` appears inside both tenant-prefixed instrument ids and clause paths, so splitting a stable ID on `/` is never correct — split on `:` into exactly three parts (see issue #5).
- **Clause path** — the third segment of a stable ID: slash-separated, hierarchical, lowercase, no parentheses. `sch1/app11/1` for an APP sub-clause, `s6c/1/a` for a section paragraph, `art9/2/b` for an EU article. One grammar for every instrument, so a second corpus needs no second parser convention.
- **Definition** — a defined term inside an instrument's interpretation section (e.g. s6's `organisation means: ...`), addressed by a clause_path segment slugged from the term itself — `s6/1/organisation` — rather than a position. s6 has no subsection/paragraph structure below its single `(1)`, just hundreds of flat, alphabetically-ordered `Definition` paragraphs; a positional index (`s6/1/1`, `s6/1/2`, ...) would silently repoint an already-issued citation whenever a later compilation inserts a new term alphabetically before an existing one — the exact failure mode a stable ID exists to prevent (issue #9's ePub format spike). The slugging algorithm (`definition_slug`) is deterministic and pure: lowercase, every run of non-alphanumeric characters folded to one `-`, ends stripped — same term, same slug, always, independent of parse order or any other term in the section. Two different terms colliding on one slug is a hard parse failure (`assert_unique_definition_slugs`), never a silently suffixed `-2` — a suffix would itself be assigned by parse order. A term renamed between compilations is a new definition at a new clause_path in the new version_id, expressed via ordinary supersession, never a mutation of the old path. The slug is derived from the term as it appears in *that* compilation, so the parser must capture the term text itself, not just the paragraph.
- **Display form** — how a clause path is rendered for a human: `sch1/app11/1` → "APP 11.1", `s6c/1/a` → "s 6C(1)(a)", `art9/2/b` → "Art 9(2)(b)". A pure function of the path, never stored: storing both would let them drift, and the path is the authority. It restores what lowercasing loses — section letter suffixes are uppercased.
- **Instrument id** — globally unique on its own. A tenant-scoped instrument is prefixed with its tenant — `acme/hr-policy` — so two companies cannot both claim `hr-policy`. Public instruments are unprefixed. A stable ID that is unique only given out-of-band context is not stable: the ID is what a citation carries and what the verifier looks up.
- **Canonical text** — a clause's text after canonicalisation. The verifier compares canonical to canonical. Lives in Cloud Storage. Never edited. _Avoid_: normalised text, cleaned text.
- **Canonicalisation** — the exact transformation producing canonical text, in order: NFC normalisation; `‘ ’` → `'`; `“ ”` → `"`; en dash and em dash → `-`; non-breaking space → space; every whitespace run collapsed to one space; ends stripped. This defines what counts as a matching citation, so it is a definition, not an implementation detail.
- **Canonicalisation version** — an integer identifying one canonicalisation. Every citation records the version it was verified under, so changing canonicalisation cannot silently invalidate citations already issued. A change to the transformation is a new version, never an edit to an existing one.
- **Position map** — how a clause is located in its source rendering for click-to-clause. Law resolves to a **synthesized anchor**: `clause_anchor_id(clause_path)`, a deterministic slug the parser writes into the stored HTML at ingest time. The source markup carries no clause-level anchor of its own — the ePub format spike (issue #9) found stable ids only at section/Part/Schedule level — so the anchor is derived from what the parser already stores (`clause_path`), never invented at render time; citation rendering recomputes the same id rather than reading one off the markup. An uploaded PDF resolves to page and character offsets captured at parse time instead. These are different mechanisms for different sources and are never joined: extracted PDF text fabricates whitespace, so deriving canonical text from it would make the verifier fail on its own corpus (D-02).
- **Chunk** — a retrieval unit derived from a clause, ≤420 tokens as counted by the **reranker's** tokenizer. One chunk belongs to at most one obligation. Chunks live in Qdrant; clauses live in Cloud Storage. The cap is set by the cross-encoder, not the embedder: `gemini-embedding-001` accepts about 2048 tokens, but a cross-encoder scores query and chunk together in one 512-token window, and overflow truncates the tail of the clause silently — losing exactly the operative words an obligation usually ends on. 420 leaves a query budget inside 512.
- **Synthetic** — tenant-scoped text invented for building and testing (the six Acme policies), not a customer's document. Marked on each chunk; anything unmarked is treated as real customer data. While the corpus holds only public law and synthetic text, generation may run outside Australia (ADR-0023); the first real tenant document closes that.
- **Policy** — a company's own document, treated like an instrument in the corpus: versions, clauses, canonical text. Unlike an instrument it gets no persisted graph node; its clauses appear only in the tenant subgraph, projected per request.
- **Library** — the admin-curated set of instruments (law, standards), shared by every tenant. Library instruments are unprefixed, scope `public`, owned by `_public`. A tenant can subscribe to or unsubscribe from a library instrument; it can never edit, withdraw or purge one.
- **Subscription** — one tenant's tick against one library instrument (ledger `tenant_instrument`). A tenant's retrieval sees its own documents plus the library instruments it subscribes to, and nothing else; the filter is built in the retrieval adapter from the ledger, never passed in by a caller. Unsubscribing deletes that row and nothing else — no store is touched, so no other tenant's view changes and prior citations still resolve. `_public` owns the library and sees all of it without a subscription.
- **Document class** — the three kinds of document in a tenant's environment, differing only in provenance and in who may act on them: **library law** (curated by the admin, shared, provenance `parsed`, subscribe/unsubscribe only); **external upload** (a law or standard the tenant supplied that the admin doesn't curate — provenance `inferred`, cited as "from a document you supplied, not verified against an official source", retrieval-only in v1: no obligations are authored for it, because that is curation, not the tenant's work); **internal policy** (the tenant's own, provenance `asserted`). The chatbot answers only from documents in the tenant's environment.
- **Corpus version** — a git tag over `corpus/instruments/`, identifying which instrument versions were loaded. Recorded on every assessment.
- **Mapping version** — a git tag over `corpus/mappings/`, identifying which obligations, conditions and crosswalks were in force. Moves independently of the corpus version: a mapping correction changes no clause text, and a new compilation changes no mapping. Recorded on every assessment; an assessment is reproducible only with both.

## Graph

- **Obligation** — a graph node for a clause that imposes a requirement. Not every clause is an obligation (recitals, definitions aren't). Carries its own stable id, independent of `clause_id`: an obligation is a human claim *about* a clause and survives a new instrument version via `SUPERSEDES`, where the clause's stable ID does not.
- **Condition** — a node that gates an obligation (turnover > $3M, actor is deployer, jurisdiction is EU). Evaluated against the **profile**.
- **Crosswalk** — a `CROSSWALKS_TO` edge between obligations or controls across instruments, authored in **mapping YAML**.
- **Mapping YAML** — hand-authored files in `corpus/mappings/`, reviewed via PR. The only source of crosswalks and obligation metadata.
- **Bitemporal** — every node carries `valid_from`, `valid_to`, `status`, `recorded_at`. `valid_to` is never null: an open-ended record carries the sentinel `NO_END_DATE` (`corpus/models.py`, `date.max`), so "is this in force on `as_of`" is always a plain `valid_from <= as_of < valid_to` — one unconditional range, not a range-or-is-null pair (issue #22). **as_of** is the mandatory date parameter on every traversal.
- **Version and retire** — the one rule for every document class: a new upload is a new `version_id`, in force from its effective date; the previous version's chunks get `valid_to` set to that date and stay where they are. Never replaced in place, never deleted on update — an issued assessment must still verify against the version it cited (ADR-0021).
- **Withdraw** — remove a tenant-owned version from retrieval at every `as_of`, keeping its text and vectors so prior citations still verify. What "delete my policy" does by default. Never applies to library law.
- **Purge** — actually delete a tenant-owned instrument or version: its chunks and every stored object version. The ledger keeps the version row with who, when and why. Refused for library law; shows the number of findings citing the target first and acts only once that number is acknowledged; audited whatever the outcome. Distinct from **unsubscribe** (library law, ledger row only) and from **replace in place** (same `version_id`, a typo fix only, never for law).
- **Supersession** — the `SUPERSEDES` edge from a new version node to the old. Nodes are never deleted or mutated. Applies to instruments only. A policy's version history lives in the ledger on `instrument_version.supersedes`, because a policy has no persisted node to carry the edge.
- **Tenant subgraph** — the small graph of one company's profile (`Organisation`, sectors, jurisdictions, actors, policy clauses). Projected per request from the ledger at `as_of`, never persisted. This is the only place a policy clause is a graph node, which is what lets a mapping traverse to one without a company document acquiring permanent graph presence.

## Retrieval

- **Track A** — graph traversal from profile to applicable obligations. Deterministic, complete, unranked.
- **Track B** — hybrid retrieval over chunks, filtered to Track A's obligation IDs. Probabilistic, ranked.
- **Channel** — one retrieval signal: dense (cosine), sparse (BM25), keyword (exact `clause_id`).
- **Fusion** — RRF over channels inside Qdrant, producing the candidates the reranker scores: the top 20 (ADR-0022).
- **Rerank** — second-stage scoring of fused candidates to top 10. Default: the **reranker service** (cross-encoder on Cloud Run, Sydney). Alternative: **ColBERT rescoring** (late-interaction multivectors inside Qdrant).
- **Router** — the single fixed decision: clause-ID regex → keyword channel, skip rerank; else full pipeline. The regex accepts a tenant-prefixed instrument id, so a policy clause ID is routed like any other.
- **Scope** — which corpus partition a chunk belongs to: `public` (law), `tenant` (company policies), `user` (one person's private additions). Scope `public` implies the reserved tenant id `_public`; `tenant_id` always names an owner, never nobody.

## Assessment

- **Profile** — a tenant's structured facts (jurisdictions, sector, size bands, actor roles, data categories, regulators). Lives in the ledger. Never embedded.
- **Claim** — a statement extracted from an uploaded document ("data will be retained for 7 years"). About a *document*: what it says. Provenance inferred until the user confirms. A claim is never promoted or mutated; it stays the record of what the document said.
- **Finding** — one claim against one obligation or policy clause: `consistent` / `conflicts` / `not_addressed` / `ambiguous`, with citations and provenance.
- **Provenance tier** — how a fact entered the system: `parsed` (deterministic), `asserted` (a user said so), `inferred` (extracted from prose), `external` (web fallback, unverified against the corpus).
- **Coverage** — for an assessment, which obligations were assessable, which weren't, and why.
- **Verifier** — the deterministic check that every citation exists in the retrieved or cached set and its span matches canonical text.
- **Repair** — the targeted regeneration of only the failing citation. Never a full regeneration.
- **Evidence** — an asserted fact that satisfies or fails a condition, created by confirming a claim or by answering a questionnaire. About a *condition*, where a claim is about a document; confirming a claim creates evidence rather than changing the claim. Documents inform; humans assert.
- **CAG prefix** — the cached prompt prefix: system prompt + obligation digest + tenant policy corpus.

## Loops

- **Loop A** — corpus maintenance: poll → parse → version → diff → PR → load → regression gate.
- **Loop B** — assessment: sign in → upload/ask → claims → Track A → Track B → rerank → generate → verify → answer → record.
- **Golden set** — labelled queries and profiles with known-correct answers. The regression gate. Lives in `corpus/golden/` as YAML carrying the same `author`, `reviewed_by` and `date` front matter as mapping YAML, because it is the same kind of artefact: a human assertion that CI enforces. The **label** — which clause is correct for a query — is always human-authored; query text may be drafted by an LLM and then reviewed. Note that the corpus version is a tag over `corpus/instruments/` only, so editing the golden set never changes it: a retrieval regression and a corpus change stay distinguishable.

## Stores

- **Ledger** — Postgres. The one store whose contents cannot be rebuilt: assessments, profile, evidence, manifest, subscriptions, chats, usage. The corpus tables in the same database (`instrument`, `instrument_version`, `clause`, `clause_version`) are a derived index kept there for join convenience; they are not the ledger and are rebuildable like any other derived store.
- **Derived store** — Qdrant and Neo4j. Rebuildable from Cloud Storage + git.
