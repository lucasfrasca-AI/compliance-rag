# DECISIONS — locked

Each of these was reasoned through at length. Reopen one only with a specific, new reason, stated in chat and recorded as a superseding ADR in `docs/adr/`. Do not quietly build an alternative.

| ID | Decision | Reason it is locked |
|---|---|---|
| D-01 | Both graphs are deterministic. Regulatory graph is hand-curated YAML in git; nothing in the graph is LLM-extracted. Tenant policy-to-law mappings may be LLM-*proposed* but are traversed only after human approval. | LLM extraction injects undetectable hallucinated obligations into the layer that must be authoritative. |
| D-02 | The LLM never authors a citation. Clause text is retrieved verbatim; a deterministic verifier blocks any citation whose span doesn't match the canonical source (after canonicalisation). | This is the product claim. |
| D-03 | Two-track retrieval. Track A (graph traversal) returns every applicable obligation, unranked and untruncated. Track B (hybrid retrieval) returns supporting text, filtered to Track A's IDs. Graph results never enter a ranking pool. | A deterministic finding must never lose a relevance contest to a topically similar paragraph. |
| D-04 | Fuse first (RRF, ~50), rerank second (cross-encoder, →10). Exact clause-ID queries skip reranking. | Rerank cost scales with candidates; a cross-encoder can only degrade an exact match. |
| D-05 | Bitemporal graph. Nodes are immutable; amendment = new version node + `SUPERSEDES` edge + `valid_to` on the old. Every traversal takes `as_of`, enforced by the query builder. Three statuses: in_force / not_yet_commenced / repealed. | Deleting superseded law silently changes issued reports. |
| D-06 | No confidence scores. Output coverage and provenance: assessable / unassessable (why), provenance tier per finding (parsed / asserted / inferred / external). | A human-authored mapping presented as a computed probability is a liability. |
| D-07 | Stack: Qdrant Cloud in `australia-southeast1` (hybrid, native RRF), Neo4j AuraDB (Cypher), **self-hosted cross-encoder on Cloud Run in Sydney** (Vertex Ranking API is not offered in AU and is CI-only), Claude on Vertex, Cloud Run, Cloud SQL ledger, OpenTelemetry → Cloud Logging (Sydney) as the only telemetry sink. | Meets the objective (real managed hybrid, real Cypher, real cross-encoder) under $100/mo with every stage inspectable and every query-time byte in Australia. |
| D-08 | Repository interfaces (`GraphStore`, `RetrievalStore`, `LedgerStore`, `Reranker`, `Embedder`, `Generator`) between the app and every external service. No Cypher or Qdrant calls outside an adapter. pgvector adapter kept as fallback. | Migration is two adapters, not a rewrite. |
| D-09 | Free-tier stores (Qdrant, Aura) hold only public law and synthetic data during build. Ledger is the single non-derivable store and is the first thing to be AU-resident and paid. Real customer policies trigger the residency move (Phase 5). | Every derived store is rebuildable from Cloud Storage + git in minutes. |
| D-10 | Product scope: proposals and documents checked against company policy and law; chat over both; citations open at the clause. No AI-system registration, no IaC scanning, no live cloud state in v1. Multi-tenancy deferred but keyed (`tenant_id` everywhere). | Focus. The graph is what makes this defensible; the scanner competes with free CSPM. |
| D-11 | CAG for the tenant policy corpus (cached prefix, ≤200k tokens); RAG for law. Never CAG the law corpus. | Law exceeds any window and changes; policies are small and tenant-owned. |
| D-12 | No agent chooses the retrieval path. The pipeline is fixed; the only routing is a regex for clause-ID lookups. | An agent deciding the graph "isn't needed" is the failure mode D-03 prevents. |
| D-13 | Phase 1 corpus is the Australian Privacy Act + APPs with a synthetic policy set; EU AI Act is Phase 4. | The differentiator is policy-to-law in one answer; the first customers' policies are written against the APPs. |
| D-15 | Reranking runs in Australia or not at all. The cross-encoder is a Cloud Run service (scale-to-zero); ColBERT rescoring in Qdrant is the sanctioned alternative. No managed reranker outside AU touches real data. | Query text and candidate chunks include customer policy text. |
| D-16 | Telemetry follows the same residency rule as data. OpenTelemetry instrumentation is written once; sinks are config in `telemetry.py`. The single sink is a Cloud Logging regional bucket in `australia-southeast1` from day one. No offshore telemetry endpoint is ever configured, not even for synthetic data. Cloud Trace receives metadata only. A trace UI is added later only by ADR: Phoenix on Cloud Run Sydney is the planned choice; self-hosted Langfuse is the unlikely alternative. | Prompts, retrieved chunks and answers in traces are the same customer data the stores protect; one sink is simpler to defend than a cut-over. |
| D-14 | Company **facts** (profile) live in the ledger and the graph; company **documents** live in Cloud Storage and Qdrant. Facts are never embedded. No company document gets a **persisted** graph node. A policy clause appears only in the ephemeral tenant subgraph, projected per request from the ledger at `as_of` and discarded with the request — which is what lets an approved policy-to-law mapping traverse to it. Uploaded documents — proposals, user-private additions — get no graph node at all, projected or persisted. User-private additions are citable but can never change applicability. | Applicability by cosine similarity is a lawsuit; per-user reality is a correctness bug. A persisted policy node would make one tenant's document part of the authoritative graph; a projected one cannot outlive the request that built it. (ADR-0018 supersedes ADR-0015.) |
