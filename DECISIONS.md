# DECISIONS — locked

Each of these was reasoned through at length. Reopen one only with a specific, new reason, stated in chat and recorded as a superseding ADR in `docs/adr/`. Do not quietly build an alternative.

| ID | Decision | Reason it is locked |
|---|---|---|
| D-01 | Both graphs are deterministic. Regulatory graph is hand-curated YAML in git; nothing in the graph is LLM-extracted. Tenant policy-to-law mappings may be LLM-*proposed* but are traversed only after human approval. | LLM extraction injects undetectable hallucinated obligations into the layer that must be authoritative. |
| D-02 | The LLM never authors a citation. Clause text is retrieved verbatim; a deterministic verifier blocks any citation whose span doesn't match the canonical source (after canonicalisation). | This is the product claim. |
| D-03 | Two-track retrieval. Track A (graph traversal) returns every applicable obligation, unranked and untruncated. Track B (hybrid retrieval) returns supporting text, filtered to Track A's IDs — in practice the clauses Track A cites, a required `LawScope` (ADR-0030), including the exceptions and qualifiers the reviewed mapping names for each obligation and the clauses inside them, which an answer given the obligation's clause is always given too, an exception marked as saying when it doesn't apply and a qualifier as saying how it is satisfied (ADR-0037, ADR-0044). Graph results never enter a ranking pool. | A deterministic finding must never lose a relevance contest to a topically similar paragraph. |
| D-04 | Fuse first (RRF), rerank the **top 20** fused candidates second (cross-encoder, →10), each library-law candidate read whole in its provision: after its chapeaux, before its paragraphs, within the chunk budget. Deliver the ten **whole**: each library-law clause with its chapeaux and paragraphs, fetched by containment, never ranked, never cut back to ten (ADR-0045). Exact clause-ID queries skip reranking, and are delivered whole too. | Rerank cost scales with candidates; a cross-encoder can only degrade an exact match. 20 (was "~50", a convention) is measured: it cleared every recall@10 exit bar on the excerpt at ~6.4 s warm vs ~16 s for 50 (ADR-0022), and on the whole compilation 50 recovers no law clause that 20 misses and loses a paraphrase query (ADR-0043). The parser stores a provision as several clauses split at its chapeau, so a paragraph ranked or delivered alone is a fragment. Reading and delivering in provision changes no chunk or vector. It leaves ranked recall@10 for law cross-clause at 0.444, and delivered-recall, a separate metric with no target, is 0.833 there (ADR-0045). |
| D-05 | Bitemporal graph. Nodes are immutable in meaning (wording may be corrected in place, acknowledged and audited, ADR-0031; a Clause node's canonical hash may be corrected in place by a parse correction of the same pinned source, acknowledged and audited clause by clause, ADR-0042); amendment = new version node + `SUPERSEDES` edge + `valid_to` on the old. Every traversal takes `as_of`, enforced by the query builder. Status (not yet commenced / in force / superseded / repealed / expired) is derived from valid time and the stored end reason, never stored (ADR-0029). The graph also holds one `Load` record per loader run that passes its checks (ADR-0034): metadata about which corpus or mapping version was written, outside the bitemporal model — no valid time, never retired, unreachable by the query builder. | Deleting superseded law silently changes issued reports. |
| D-06 | No confidence scores. Output coverage and provenance: assessable / unassessable (why), provenance tier per finding (parsed / asserted / inferred / external). | A human-authored mapping presented as a computed probability is a liability. |
| D-07 | Stack: Qdrant Cloud in `australia-southeast1` (hybrid: Qdrant scores dense and sparse; the adapter cuts each channel by `chunk_id` on a tie and fuses with RRF, ADR-0046), Neo4j AuraDB (Cypher), **self-hosted cross-encoder on Cloud Run in Sydney** (Vertex Ranking API is not offered in AU and is CI-only), Claude on Vertex — **not served from Sydney** (corrected by ADR-0023): `claude-sonnet-5` at the US multi-region endpoint during the build phase only (ADR-0024) — Cloud Run, Cloud SQL ledger, OpenTelemetry → Cloud Logging (Sydney) as the only telemetry sink. | Meets the objective (real managed hybrid, real Cypher, real cross-encoder) under $100/mo with every stage inspectable and every query-time byte in Australia except build-phase generation on public law and synthetic data (ADR-0023). |
| D-08 | Repository interfaces (`GraphStore`, `RetrievalStore`, `LedgerStore`, `Reranker`, `Embedder`, `Generator`) between the app and every external service. No Cypher or Qdrant calls outside an adapter. pgvector adapter kept as fallback. | Migration is two adapters, not a rewrite. |
| D-09 | Free-tier stores (Qdrant, Aura) hold only public law and synthetic data during build. Ledger is the single non-derivable store and is the first thing to be AU-resident and paid. Real customer policies trigger the residency move (Phase 5). | Every derived store is rebuildable from Cloud Storage + git in minutes. |
| D-10 | Product scope: proposals and documents checked against company policy and law; chat over both; citations open at the clause. No AI-system registration, no IaC scanning, no live cloud state in v1. Multi-tenancy deferred but keyed (`tenant_id` everywhere). | Focus. The graph is what makes this defensible; the scanner competes with free CSPM. |
| D-11 | CAG for the tenant policy corpus (cached prefix, ≤200k tokens); RAG for law. Never CAG the law corpus. A clause in the prefix is never also retrieved (ADR-0033). | Law exceeds any window and changes; policies are small and tenant-owned. |
| D-12 | No agent chooses the retrieval path. The pipeline is fixed; the only routing is a regex for clause-ID lookups. | An agent deciding the graph "isn't needed" is the failure mode D-03 prevents. |
| D-13 | Phase 1 corpus is the Australian Privacy Act + APPs with a synthetic policy set; EU AI Act is Phase 4. | The differentiator is policy-to-law in one answer; the first customers' policies are written against the APPs. |
| D-15 | Reranking runs in Australia or not at all. The cross-encoder is a Cloud Run service (scale-to-zero); ColBERT rescoring in Qdrant is the sanctioned alternative. No managed reranker outside AU touches real data. | Query text and candidate chunks include customer policy text. |
| D-16 | Telemetry follows the same residency rule as data. **Residency is unconditional for telemetry, Cloud Storage, the ledger and Qdrant (Aura Free stays under D-09's existing build exception). Generation is the single exception, and only while the corpus is public law plus synthetic data: it runs at the US multi-region endpoint (ADR-0024), behind a gate that refuses offshore generation at startup, refuses any real (non-synthetic) tenant upload at ingest (ADR-0023), and, per answer, refuses a question from a member not registered as a build-phase tester, and any tenant text read from the bucket (the CAG prefix, a clause to repair) that isn't registered synthetic (ADR-0032).** OpenTelemetry instrumentation is written once; sinks are config in `telemetry.py`. The single sink is a Cloud Logging regional bucket in `australia-southeast1` from day one. No offshore telemetry endpoint is ever configured, not even for synthetic data. Cloud Trace receives metadata only. A trace UI is added later only by ADR: Phoenix on Cloud Run Sydney is the planned choice; self-hosted Langfuse is the unlikely alternative. | Prompts, retrieved chunks and answers in traces are the same customer data the stores protect; one sink is simpler to defend than a cut-over. |
| D-17 | The product is a platform over a curated **library**. The admin curates library law, shared by every tenant; each tenant **subscribes** to the instruments that apply to it, uploads its own policies and may upload external documents. A tenant's retrieval sees only its own documents plus its subscribed library instruments, enforced inside the retrieval adapter's filter from the ledger — never a caller-supplied filter. Unsubscribe deletes the subscription row only. | The chatbot must answer only from what is in the tenant's environment, and library law is shared: one tenant unticking an instrument must never change what another tenant can see or cite. (ADR-0020.) |
| D-18 | **Version and retire, for everything** — law, external uploads and policies. A new upload gets a new `version_id`; the previous version's chunks get `valid_to` and stay in place. Nothing is replaced in place or deleted on update. Removal is three explicit states: **unsubscribe** (library law; subscription row only), **withdraw** (tenant-owned; out of retrieval, text and vectors kept), **purge** (tenant-owned; actually deleted, ledger row kept with who/when/why). Purge guardrails live in the adapter: library law refused, findings-citing count shown and acknowledged before acting, every outcome audited. Replace-in-place is a typo-fix path only, never for law. Library law's stored text changes only by a corpus revision (ADR-0042): a parse correction of the same pinned source, in place under the same `version_id`, acknowledged and audited clause by clause, or an amendment, which is a new version. | An assessment issued in March must still verify against the document as it read in March; deletion makes an issued report silently uncheckable. One rule for law and policy is one code path, and D-05 already mandates retention for law. (ADR-0021.) |
| D-14 | Company **facts** (profile) live in the ledger and the graph; company **documents** live in Cloud Storage and Qdrant. Facts are never embedded. No company document gets a **persisted** graph node. A policy clause appears only in the ephemeral tenant subgraph, projected per request from the ledger at `as_of` and discarded with the request — which is what lets an approved policy-to-law mapping traverse to it. Uploaded documents — proposals, user-private additions — get no graph node at all, projected or persisted. User-private additions are citable but can never change applicability. | Applicability by cosine similarity is a lawsuit; per-user reality is a correctness bug. A persisted policy node would make one tenant's document part of the authoritative graph; a projected one cannot outlive the request that built it. (ADR-0018 supersedes ADR-0015.) |
